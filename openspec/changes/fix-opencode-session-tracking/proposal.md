## Why

OpenCode session tracking is completely broken — sessions are never created because there is no start hook, and the `opencode-stop` handler fires on every LLM response (the `after` hook in `~/.opencode/config.json` runs per-turn, not per-session). Users see "no open opencode session found" in the log and zero OpenCode sessions in the dashboard or `finn sessions` output.

## What Changes

- Replace the `after` hook in `~/.opencode/config.json` with a proper OpenCode plugin using `session.created` and `session.deleted` events
- Add `handleOpencodeStart()` to create sessions on `session.created`
- Update `handleOpencodeStop()` to run on `session.deleted` instead of the `after` hook
- Remove the `after` hook registration from `finn setup`
- Register a plugin file at `~/.config/opencode/plugins/finnisher.ts` during setup
- OpenCode plugin receives `CLAUDE_PROJECT_DIR` env var (same as Claude Code) for project path resolution

## Capabilities

### New Capabilities
- `opencode-plugin-support`: OpenCode plugin-based session lifecycle tracking using `session.created` and `session.deleted` events

### Modified Capabilities
- `session-repo-context`: Replace OpenCode `after` hook registration with plugin registration in `finn setup`

## Impact

- `src/hooks/opencode.ts` — add `handleOpencodeStart()`, update `handleOpencodeStop()` to use project path from env var
- `src/cli/commands/setup.ts` — replace `after` hook registration with plugin file creation in `~/.config/opencode/plugins/`
- `src/cli/commands/hook.ts` — add `opencode-start` event to dispatcher
- `~/.opencode/config.json` — remove `after` hook on next `finn setup` run
- `~/.config/opencode/plugins/finnisher.ts` — new plugin file generated by setup
