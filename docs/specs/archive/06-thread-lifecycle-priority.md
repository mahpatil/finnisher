# Spec: Thread Lifecycle, Priority, and List Filtering

**Issue**: n/a
**Status**: Draft
**Date**: 2026-05-24

## Problem

Threads currently use an operational-status vocabulary (`active`, `waiting`, `blocked`, `done`) that conflates lifecycle stage with work state. There is no way to sequence threads by intent (do now vs. park for later), no way to soft-remove threads without deleting them, and no filter UI on the thread list — forcing users to scroll through all threads to find what matters.

## Context

The current schema has `ThreadState = 'active' | 'waiting' | 'blocked' | 'done'`. The Momentum Engine adds a `stalled` boolean and `momentum` score. The web dashboard groups threads by state. The CLI `finn list` has a `--state` filter but no priority filter. The `VALID_STATES` array is duplicated in `status.ts` and `list.ts`.

The new model cleans up the lifecycle vocabulary — replacing `active` with `new`/`open` and `done` with `closed`, adding `archived` — while keeping `waiting` and `blocked` as distinct operational states. A new `priority` field (`now | next | later | out`) handles sequencing intent independently of state. Priority is orthogonal: a blocked thread can still be `now`.

## Acceptance Criteria

- [ ] Given the schema, when a thread is created, its `state` is one of `new | open | waiting | blocked | closed | archived` and its `priority` is one of `now | next | later | out` (default `later`)
- [ ] Given a migration runs, when existing threads are present, then `active` → `open` and `done` → `closed`; `waiting` and `blocked` are preserved as-is with no data loss
- [ ] Given `finn archive <id>`, when called on any non-archived thread, then the thread state becomes `archived` and a confirmation is printed
- [ ] Given `finn unarchive <id>`, when called on an `archived` thread, then the thread state becomes `open` and a confirmation is printed
- [ ] Given `finn list`, when called with no flags, then `archived` threads are excluded and all other states are shown
- [ ] Given `finn list --archived`, when called, then only `archived` threads are shown
- [ ] Given `finn list --priority <value>`, when called with `now|next|later|out`, then only threads matching that priority are shown
- [ ] Given `finn status <id> <state>`, when called with the new state vocabulary (`new|open|waiting|blocked|closed|archived`), then it sets the state correctly; the old `active` and `done` vocabulary is rejected with a clear error
- [ ] Given `finn priority <id> <priority>`, when called with `now|next|later|out`, then it updates the thread priority and prints confirmation
- [ ] Given the web thread list tab, when rendered, then a filter bar appears above the list with state chips: `All` / `New` / `Open` / `Waiting` / `Blocked` / `Closed` / `Archived` (Archived deselected by default)
- [ ] Given the web thread list tab, when rendered, then a second filter row shows priority chips: `All` / `NOW` / `NEXT` / `LATER` / `OUT`
- [ ] Given a thread card in the web UI, when rendered, then the priority badge is visible with the correct colour: NOW=red, NEXT=amber, LATER=blue, OUT=grey
- [ ] Given a thread card in the web UI, when the archive button is clicked, then the thread moves to `archived` state and is removed from the current view
- [ ] Given an archived thread in the web UI (Archived filter active), then an unarchive button is visible and clicking it moves the thread back to `open`
- [ ] Given `GET /api/v1/threads`, when called with no query param, then `archived` threads are excluded; `?state=archived` returns only archived threads
- [ ] Given `GET /api/v1/threads`, when called with `?priority=now`, then only `now`-priority threads are returned

## Technical Design

### Data Model Changes

**`src/db/schema.ts`**

```ts
export type ThreadState    = 'new' | 'open' | 'waiting' | 'blocked' | 'closed' | 'archived'
export type ThreadPriority = 'now' | 'next' | 'later' | 'out'

export const THREAD_STATES:     readonly ThreadState[]    = ['new','open','waiting','blocked','closed','archived']
export const THREAD_PRIORITIES: readonly ThreadPriority[] = ['now','next','later','out']
```

Add two columns to `threads` table:

```ts
priority:   text('priority').$type<ThreadPriority>().notNull().default('later'),
archivedAt: integer('archived_at', { mode: 'timestamp_ms' }),
```

**Migration `0003_thread_lifecycle_priority.sql`** (generated by Drizzle, then hand-edited to add data transforms):

```sql
-- Data transform: rename active→open, done→closed (waiting/blocked unchanged)
UPDATE threads SET state = 'open'   WHERE state = 'active';
UPDATE threads SET state = 'closed' WHERE state = 'done';

-- New columns
ALTER TABLE threads ADD COLUMN priority    text NOT NULL DEFAULT 'later';
ALTER TABLE threads ADD COLUMN archived_at integer;
```

### API / Interface Changes

**Endpoints**

| Method | Path | Change |
|--------|------|--------|
| GET | `/api/v1/threads` | Add `?state=` and `?priority=` query params; exclude `archived` when neither param is set |
| PATCH | `/api/v1/threads/:id` | Accept `priority` field in body alongside existing `state` |

**State filter logic (GET):**
- No `?state` param → return all states except `archived`
- `?state=archived` → return only archived
- `?state=open` → return only that state (same for all valid values)

**`ThreadWithMeta` interface** — add:
```ts
priority:   string
archivedAt: string | null
```

### Key Logic

- `updateState(id, 'archived')` sets `archivedAt = new Date()`; `updateState(id, any-non-archived)` clears `archivedAt`
- `updateState(id, 'closed')` sets `completedAt` (same as current `done` logic)
- `touchThread` skips `closed` and `archived` (was: skips `done`)
- `isStalled` excludes `closed` and `archived` (was: excludes `done`)
- `activeThreadCount` and `overloadWarning` count `new + open` threads (was: counted `active`)
- New `updatePriority(id: string, priority: ThreadPriority): void` function in `src/db/threads.ts`
- `VALID_STATES` duplication in `status.ts` and `list.ts` eliminated — import `THREAD_STATES` / `THREAD_PRIORITIES` from `schema.ts`

### Priority colours (web)

| Priority | MUI token | Approx hex |
|----------|-----------|-----------|
| NOW | `error.main` | `#ef4444` |
| NEXT | `warning.main` | `#f97316` |
| LATER | `info.main` | `#3b82f6` |
| OUT | `text.disabled` | `#6b7280` |

## Test Scenarios

### Happy Path

1. `finn archive abc123` on an open thread → `✓ Thread abc123 archived`, state = `archived`
2. `finn unarchive abc123` → `✓ Thread abc123 unarchived`, state = `open`
3. `finn archive abc123` on a `blocked` thread → succeeds (any non-archived state is archivable)
4. `finn list` → shows new/open/waiting/blocked/closed, no archived
5. `finn list --archived` → shows only archived threads
6. `finn list --priority now` → shows only `now`-priority threads across all non-archived states
7. `finn priority abc123 now` → `✓ Thread abc123 priority set to now`
8. `finn status abc123 waiting` → succeeds (state transitions within new vocabulary)
9. `GET /api/v1/threads` → no archived threads in response
10. `GET /api/v1/threads?state=archived` → only archived threads
11. `GET /api/v1/threads?priority=now` → only `now` threads
12. Web: select "Waiting" chip → only waiting threads shown; priority filter still applies on top
13. Web: click archive button on a card → card disappears from current view

### Edge Cases

1. `finn archive <id>` on already-`archived` thread → `Thread is already archived`
2. `finn unarchive <id>` on a non-archived thread → `Error: Thread is not archived`
3. `finn status <id> active` (old vocabulary) → `Error: Invalid state "active". Valid: new, open, waiting, blocked, closed, archived`
4. `finn status <id> done` (old vocabulary) → same error
5. Migration with zero existing threads → runs cleanly
6. Web: all threads archived → empty state message shown in list
7. `finn list --state waiting --priority now` → shows only waiting+now threads

### Error Cases

1. `finn archive <nonexistent-id>` → `Error: Thread not found: <id>`
2. `finn priority <id> critical` → `Error: Invalid priority "critical". Valid: now, next, later, out`
3. `PATCH /api/v1/threads/:id` with `{ priority: "critical" }` → 422 `{ error: { code: "INVALID_PRIORITY", message: "…" } }`
4. `PATCH /api/v1/threads/:id` with `{ state: "active" }` → 422 `{ error: { code: "INVALID_STATE", message: "…" } }`

## Out of Scope

- Bulk archive/unarchive (Phase 2)
- Priority-based auto-sorting on the Momentum dashboard (Phase 2)
- Recalibrating Momentum Engine scores beyond updating state name references
- Priority as a blocking gate (threads never change state based on priority)
- Adding priority to hook/session tracking output
- URL-persisted filters in the web UI
